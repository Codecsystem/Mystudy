# 笔记正文整理规范

本规范用于 Board 2/3 的正式 `.md` 笔记。文件名含 `trick` 的随笔，以及 `板子/config/board_config.json` 中 `note_style.blacklist_names` 列出的文件，暂不强制整理。

## 基本原则

- 源笔记只负责正文内容；文件标题由板子生成器根据文件名注入。
- 整理目标是让笔记更适合打印板子：结构清楚、公式稳定、代码和表格不挤成一团。
- 优先保留原作者的表达、信息密度和竞赛笔记风格，不把笔记扩写成教材。
- 只在局部重写标题、短句和连接语；不得改变知识点含义、公式结论、代码逻辑和图片引用。
- 使用 UTF-8、LF 换行，避免行尾两个空格。
- 段落之间用空行分隔，不用手工空格控制换行。

## 正文组织

- 保持原有知识点顺序。只有明显错位或重复的段落，才做小范围移动或合并。
- 标题应服务于检索，不强行套“定义 / 结论 / 证明 / 实现”模板。
- 原文中简洁有效的短句、提醒和口语化记忆点可以保留。
- 关键结论可以加粗或单独成段，但不要把每一句都改成“结论：……”。
- 证明和推导以不丢信息为第一目标，只整理换行、对齐和必要的说明。
- 代码块前可补一句用途说明，但不要大段解释显然的代码。

## 不推荐的整理方式

- 不要为了统一而把每个主题都扩写成教材式段落。
- 不要大量新增原文没有的概念解释、背景知识或证明细节。
- 不要把紧凑公式强行拆成很多短行，导致板子占用更多空间。
- 不要删除原文中有用的口语化提示，例如“注意”“其实”“可以发现”这类记忆钩子。
- 不要把作者的判断改成过度正式但信息更少的套话。

## 标题

- 标题前后都留一个空行，文件开头的第一个标题除外。
- 源 `.md` 可以从 `###` 或 `####` 开始；如果本地阅读器标题偏大，优先从 `####` / `#####` 开始。
- 同一文件内标题层级保持相对一致，不要无意义跳级；生成器会把该文件内最浅标题映射为板子正文的一级标题。
- 标题命名尽量短而明确，例如“定义”“性质”“线性筛实现”“Dilworth 定理”。
- 不要为了加粗正文使用标题；短句提示使用 `**文字**` 或普通段落。

## 数学公式

- 行内公式使用 `$...$`，美元符号紧贴公式内容。
- 行间公式统一使用多行形式：

```markdown
$$
f(n) = \sum_{d \mid n} g(d)
$$
```

- 不使用单行 `$$...$$`，不使用 `\[...\]`。
- 同余括号优先写 `\pmod{m}`。
- 多行推导优先使用 `aligned`，不要让公式块正文行以裸 `=` 开头。

## 代码块

- 代码块必须写语言标记，例如 ` ```cpp `。
- 代码块前后保留空行。
- 规范化笔记时不改代码逻辑、变量名、缩进风格。

## 列表、表格和图片

- 列表项中嵌套公式或代码块时，公式/代码块前后留空行。
- 表格前后留空行，表头分隔线保持标准 Markdown 表格语法。
- 图片使用相对当前 `.md` 文件的路径，例如 `![说明](md.img/image.png)`。
- 图片前后留空行，必要说明写在图片附近的普通段落或引用块中。

## 水平线

- 正式笔记中不要直接写独占行 `---`。
- 需要分隔线时写：

```markdown
<!-- board:hr -->
```

生成器会将它转换为板子中的横线。
